# AGENTS.md

## Quick start
- The Hub and its static projects are dependency-free sites. Open their `index.html` files directly.
- The root `index.html` is the hub page that links to the sub-projects.
- `.github/workflows/pages.yml` assembles the static projects and deploys one GitHub Pages artifact.

## Project structure
- `index.html` / `script.js` / `styles.css` — the hub landing page
- `ManDayRin/` — Installable, offline-first Mandarin PWA with a 52-week themed course: a new 15-word list every Monday (week 1 = the Monday of first launch; earlier weeks stay open, later ones locked), 2 sentence patterns and 3 read-along scenarios per week. Content lives in `weeks.js` (`MANDAYRIN_COURSE`: `levels`, `themes` for all 52 weeks, character `names`, and `weeks[n]` with `words` `[hanzi, pinyin, en, kind, exZh, exPy, exEn]`, `patterns`, `scenarios` with `cast` + `lines`); all 52 weeks are written (780 words). Rule: no word appears in two weeks' lists; scenarios use only this and earlier weeks' words. Scenario lines are tokenized by greedy longest match against unlocked words (names never split) so each word is tappable. Words tab lists every unlocked word with a quiz. Audio: every word, example, pattern example and scenario line is a recording (device speech is only a fallback, because it is muted by the iPhone silent switch). After editing `weeks.js`, run `python ManDayRin/build_audio.py` (needs Node + `pip install edge-tts`; clips cached in gitignored `.audio-cache/`) to rewrite `audio/week-NN-{words,lines}.<hash>.bin` (concatenated MP3s) and `audio/index.js` (`MANDAYRIN_AUDIO` byte ranges; clip refs `week:t|w<i>|x<i>|p<i>|s<scenario>-<line>`); each scenario character has their own voice (`CAST_VOICES`). Packs load per week on demand and live in the service worker's `mandayrin-audio` cache. `?week=N` previews week N unlocked (not saved)
- `StoryTime/` — Installable Mandarin story reader with three levels, synchronized device speech, and plain-text story files in `StoryTime/stories/`; run `python3 StoryTime/build_stories.py` to rebuild the library (see `StoryTime/README.md`)
- `smolov/` — Smolov Jr. strength training calculator (static HTML/CSS/JS)
- `paypers/` — PubMed paper discovery app with swipe interface (static HTML/CSS/JS)
- `laser-engraving/` — Laser engraver bed layout tool with CAD-style SVG engine
- `hollowkeep/` — Installable, offline colony-defence game (Rise to Ruins–style): Phase 2 economy plus a compact Phase 3 night war, Phase 4 corruption/god powers and Phase 5 depth. All sim files are pure data advanced by `World.tick()` at a fixed 10 Hz (`SimClock`, pause/1x/2x/3x) and run under Node: `js/sim.js` (map, tiles incl. raised Cliff, clock); `js/colony.js` (villagers with hunger/rest/hp/mood and traits Brave/Lazy/Strong/Night-owl/Hero, job board with gather/deliver/build/craft/repair/douse jobs, flee-to-keep and fight states, 15 buildings in Village/Industry/Defence trays, production chains sawmill→planks, kiln→bricks, smelter→iron, smithy→tools (+25% work), event log `chronicle`; tuning in `BAL`, `DAY`, `BUILDINGS`); `js/war.js` (dawn omen, dusk portals, waves of Husk/Wisp/Runner/Brute/Spitter plus a Siege Golem every 10th night, a Dijkstra flow field where walls cost more the more hp they have, towers/keep arrows, fire that lightning and tower arrows start and wells douse); `js/blight.js` (corruption nodes left by closed portals and surviving wisps, creeping field that kills trees/crops and hurts villagers, shrine wards, pulls portals closer); `js/divine.js` (mana, powers Lightning/Heal/Raise/Lower/Cleanse with costs and cooldowns, 15-node tech tree in Economy/Defence/Divine bought with gold + mana); `js/story.js` (dawn events: caravan trades, drought, blood moon, wandering hero, plague). `js/render.js` + `js/render-war.js` draw the baked map, buildings, villagers, monsters, the animated purple creep with its dashed boundary, fire, arrows, lightning and the omen arrow; `js/camera.js` handles pan/zoom/taps; `js/audio.js` synthesises all sound with Web Audio (no files): sim events → sfx, a generative music bed that follows darkness and the fight, three-state speaker button (all / effects / off, saved in localStorage `hollowkeep.audio`), unlocked on first tap; `main.js` owns the HUD (stores/gold/mana bar, build trays with line-painted walls, jobs, tech, power radial menu + targeting, chronicle, caravan panel, cards, game-over) and exposes `HK.debug` (incl. `skipTo(t)`). `design.html` holds the Phase 0 design doc. URL params `?seed=N&agents=N` (agents = Phase 1 load-test wanderers, default 0). Keys: Space, 1–3, Q/W/E/R/T powers, L chronicle
- `TaskSchedule/` — Installable, offline-first Task & Schedule PWA (vanilla `app.js`, `sw.js`, `manifest.webmanifest`): Schedule tab with a Week/Month switch (week strip, or a Monday-first month grid showing up to two event/due-task chips per day plus +N; choice saved in localStorage `taskschedule.range`), per-day due tasks and an hourly timeline of events; Tasks tab split into Today and All lists (each task has a move button; a task is in Today when its `planned` date is today, or earlier and still undone), swipe a task left for Edit/Delete (delete has an Undo toast); done tasks are deleted 24 h after `doneAt` (`purgeDone()` runs on every render and records the deletion so it syncs); one add/edit sheet (bottom sheet on phones) for tasks (title, Due quick picks None/Today/Tomorrow/Weekend/Next week + date picker, Add to Today switch, collapsible notes) and events (date, start/end); task rows say "Due Friday" / "Overdue". Plan week (Schedule tab) books one session a day for every unfinished task with a due date, from up to 7 days before until the day before (or today), 10 min growing to 30 min, in free time 8am–9pm searching from 4pm first with a 5-min buffer; sessions are events with `auto: true` + `taskId` (dashed in the timeline and month grid); re-planning replaces a task's upcoming sessions; completing a task drops its upcoming sessions, deleting it (swipe, editor or the 24 h purge) drops all of them; one shared toast offers Undo for deletes and plans. Protocols tab (`protocols.js`): build protocols from Action blocks (text), Protocol blocks (`{type: "protocol", protocolId}`: another protocol run in place; added with + Protocol or made with Select mode, which moves the picked blocks into a new protocol and leaves one Protocol block; `flatten()` expands them at run start with each step's `path`, loops are blocked when adding and skipped when running; deleting a protocol removes the blocks that point to it) and Wait blocks (edited as one line: [words before] [timer chip] [words after], stored in `text` as "before ___ after"; shown as "Incubate for 10 minutes on the shaker") (microwave-style h/m/s keypad with quick-add chips, or Overnight = no time setting; ready once the calendar day changes, then waits for Continue, never auto-advances or alarms); reorder/duplicate/delete blocks; actions can contain blanks (`___`, inserted with + Blank) and each action block has one editable preset list (`block.presets`; an entry is an array with one value per blank, filled in order, or a single value that fills the current blank; edited under the block with one field per blank: Add, × to remove, tap to load back for editing); those per-step lists are labelled "Quick picks". Protocol presets (`p.variants: [{id, name}]`, managed in the bar under the title): each step has "In" toggles (`block.skip` = ids of presets that leave it out) and, for blanks, one value per blank per preset (`block.values[id]`); Run asks which preset to use (or No preset), `flatten(p, path, seen, variantName)` drops skipped steps and attaches `fill`, `beginRun` pre-fills `run.fills`, the run title gets " · <preset>", and nested protocols use their own preset with the same name (Select mode copies the parent's presets into the new protocol); in Run mode that block's quick picks pop up for the next empty blank (or a tapped one), with an Other field, and the chosen values live in `run.fills`; Run mode walks the steps with a live countdown, pause/+1 min/skip for timed waits, and a beep/vibration/notification when a timed wait ends (only while the page is alive). Sync (`sync.js`): optional two-way sync of tasks, events and protocols to one Directus collection (`taskschedule_items`: id, kind task/event/protocol/setting, data json, updated ms, deleted) using a static token: `make-sync-config.mjs` reads `DIRECTUS_SYNC_TOKEN` + `TASKSCHEDULE_PASSPHRASE` from the repo-root `.env` and writes the committed `sync-config.js` (token AES-GCM encrypted, PBKDF2 key from the normalised passphrase); each device unlocks once in the cloud-button dialog and keeps the token in localStorage (a token can also be pasted by hand); newest `updated` wins and deletions are kept as records. `directus-setup.mjs` creates the collection; `DIRECTUS.md` covers the sync user, token and CORS. Responsive: phone column below 720px; iPad portrait (720px+) widens with taller month cells (4 chips); 1000px+ (computer, iPad landscape) moves the tabs to a left rail and splits Schedule into calendar + due list (`.sched-cal`) and a sticky timeline (`.sched-day`); with a mouse, drag a task to swipe and double-click to edit. Bump `CACHE_NAME` in `sw.js` and the `?v=` strings when changing assets
- `conversions/` — Local file converter, all client-side: audio/video → MP3 (vendored `lame.min.js`, a lamejs build), WAV via Web Audio `decodeAudioData`, Opus/M4A/WebM/MP4 via MediaRecorder (feature-detected, real-time), animated GIF (vendored `gifenc.js`); images → JPEG/PNG/WebP via canvas plus BMP/GIF/ICO/PDF hand-written encoders; CSV/TSV ⇄ JSON; TXT/MD → PDF; batch results download as a store-only ZIP

Each static sub-project has its own `index.html`.

## Backend / APIs
- `smolov/supabase.js` talks to Supabase PostgREST (`/rest/v1`). Config comes from `smolov/config.js` (gitignored, generated from the repo-root `.env`), which sets `window.SMOLOV_CONFIG` with the project URL and the **publishable/anon** key only. The `.env` `SUPABASE_SECRET_KEY` must never reach client code. `config.example.js` is the committed template; `supabase-schema.sql` creates the `lift_maxes` and `smolov_plans` tables plus permissive anon RLS policies (run once in the Supabase SQL editor). The client keeps the original `LiftMaxesAPI` / `SmolovPlansAPI` surface so `script.js` is unchanged.
- `paypers/app.js` fetches from Europe PMC REST API (`www.ebi.ac.uk/europepmc/webservices/rest/search`).

## Editing conventions
- All CSS and JS is vanilla.
- CSS uses cache-busting query strings on `<link>` and `<script>` tags (e.g., `styles.css?v=12`). Increment the version when changing assets in `smolov/`.
- Most JS uses IIFE-style patterns and DOM-ready callbacks (`DOMContentLoaded`). Exception: `paypers/app.js` uses module-scope `const` instead.
- Every sub-project uses a view state machine (loading → setup → main, or welcome → tabs, or onboarding → viewer).
- `paypers/` has two tabs: Swipe (card stack) and Saved (paper list). Double-tapping the Saved tab triggers a full state reset.
- `laser-engraving/` has a CAD engine rendering to SVG with pan/zoom/draw/drag tools. `doggo.gc` is a sample G-code file.

## Persistence
- `ManDayRin/` — localStorage (`mandayrinState.v2`: course start Monday, reminder settings, pinyin/English toggles; reminder settings migrate from the old `mandayrinState.v1`) plus service-worker IndexedDB for best-effort background reminder checks
- `smolov/` — Supabase (Postgres via PostgREST): `lift_maxes`, `smolov_plans`
- `StoryTime/` — localStorage (`storytime.v1`: reading progress and listening preferences); app shell and starter stories cached by service worker
- `paypers/` — localStorage (`paypersState`)
- `laser-engraving/` — localStorage (`laserEngraving_bedSize`, `laserEngraving_presets`)
- `hollowkeep/` — IndexedDB `hollowkeep`/`saves`/`autosave` holds the whole World, written by `js/save.js` (generic object-graph serializer: keeps shared references, typed arrays, seeded RNG state; bump `SAVE_VERSION` when state shape changes incompatibly). Autosaves at dawn and when the app is backgrounded (which also pauses); cleared on game over; skipped for `?seed=` runs. Any new state class must be exported on `HK` so the serializer can find it, and fields must not hold closures (rebuild them in `save.js`, as for Blight's noise). `node hollowkeep/tests/save-roundtrip.js` checks a loaded save stays identical to the original. Service-worker Cache Storage (`hollowkeep-v*`) for offline play
- `TaskSchedule/` — localStorage (`taskschedule.v1`: `tasks`, `events`, `protocols`, `settings` (currently unused) arrays plus `deleted` records; `taskschedule.run`: the in-progress protocol run, device-only; `taskschedule.sync`: Directus URL/token, device-only, never synced) plus optional Directus sync; service worker is network-first with cache fallback; app shell cached by service worker (`taskschedule-v*`)
- `conversions/` — none; source files are decoded in memory and results download straight to disk
